Ejecutar SIHS en Windows con WSL2

Instala Ubuntu dentro de Windows, conecta Docker Desktop, prepara Supabase CLI y ejecuta el sistema completo con make. Sigue los pasos en orden.

Entorno local de demostración: no usa producción
Antes de empezar1. WSL22. Docker3. Ubuntu4. Supabase5. Repositorio6. DemoAyuda

Antes de empezar

Qué ocurrirá. Windows sigue siendo tu sistema principal. Ubuntu se ejecuta dentro de Windows con WSL2. Desde Ubuntu usarás los comandos de SIHS; Docker Desktop levantará Supabase, PostgreSQL, FastAPI, React y Mailpit.

Necesitas

  • Windows 10 versión 2004 o superior, o Windows 11.
  • Permiso de administrador para instalar WSL2 y Docker Desktop.
  • Internet estable la primera vez y 12 GB libres en disco.
  • Acceso al repositorio de SIHS.

Reglas importantes

  • Usa la terminal Ubuntu, no PowerShell, para make.
  • No instales docker.io dentro de Ubuntu.
  • No levantes SIHS con docker compose up manualmente.
  • No subas archivos .env ni claves a Git.

1. Instalar WSL2 y Ubuntu

1

Abre PowerShell como administrador

Busca “PowerShell”, clic derecho y elige Ejecutar como administrador. Ejecuta:

wsl --install -d Ubuntu

Reinicia el computador si Windows lo solicita.

2

Actualizar y comprobar

Tras reiniciar, abre de nuevo PowerShell como administrador:

wsl --update
wsl --set-default-version 2
wsl --list --verbose

Debe aparecer Ubuntu con VERSION 2.

3

Abre Ubuntu

Desde Inicio abre “Ubuntu”. La primera vez te pedirá un usuario y contraseña Linux. No tienen por qué coincidir con los de Windows. Al escribir la contraseña no verás caracteres; es normal.

2. Instalar y conectar Docker Desktop

  1. Instala Docker Desktop para Windows.
  2. Ábrelo y espera que indique que Docker está iniciado.
  3. En Settings → General, activa Use the WSL 2 based engine.
  4. En Settings → Resources → WSL Integration, activa Ubuntu y pulsa Apply & Restart.
Si no aparece WSL Integration: Docker puede estar en modo contenedores Windows. En el icono de Docker de la barra de tareas selecciona Switch to Linux containers.

De vuelta en Ubuntu, comprueba la conexión:

docker version
docker compose version

Los dos comandos deben mostrar una versión.

3. Preparar Ubuntu

Instala las herramientas que usan los scripts de SIHS:

sudo apt update
sudo apt install -y git make curl ca-certificates unzip

Comprueba que quedaron disponibles:

git --version
make --version
curl --version
Evita OneDrive. No clones el código dentro de OneDrive o Escritorio de Windows: la sincronización puede ralentizar o bloquear archivos que Docker monta. Usaremos ~/src dentro de Ubuntu.

4. Instalar Supabase CLI

SIHS usa Supabase CLI para iniciar base de datos, autenticación, API y Studio locales. El repositorio ya tiene configuración de Supabase: no ejecutes supabase init.

1

Revisar arquitectura

uname -m

x86_64 necesita el paquete linux_amd64.deb; aarch64 necesita linux_arm64.deb.

2

Descargar e instalar

Desde Windows abre las versiones oficiales de Supabase CLI y descarga el archivo .deb más reciente para tu arquitectura. Si se descargó en Descargas de Windows:

cd /mnt/c/Users/TU_USUARIO_WINDOWS/Downloads
ls supabase_*_linux_amd64.deb
sudo apt install ./supabase_*_linux_amd64.deb

Reemplaza TU_USUARIO_WINDOWS por el nombre de la carpeta de usuario de Windows, por ejemplo Wilfer.

3

Comprobar

supabase --version
supabase --help

5. Descargar SIHS y cambiar a la rama

Para una instalación nueva: sustituye URL_DEL_REPOSITORIO por la URL de GitHub que les compartieron.
1

Clonar dentro de Ubuntu

mkdir -p ~/src
cd ~/src
git clone URL_DEL_REPOSITORIO Develop-SIHS
cd Develop-SIHS
2

Elegir la rama correcta

git fetch origin --prune
git switch fixes-multiples-nicol
git pull --ff-only origin fixes-multiples-nicol
git branch --show-current

La última línea debe mostrar fixes-multiples-nicol.

Si ya existe el repositorio

Entra a su carpeta, revisa los cambios locales y actualiza. Si git status --short muestra archivos, no uses git reset --hard; guarda el trabajo o pide ayuda.

cd ~/src/Develop-SIHS
git status --short
git fetch origin --prune
git switch fixes-multiples-nicol
git pull --ff-only origin fixes-multiples-nicol

6. Iniciar la demo local

1

Preparar la configuración local

La demo genera las credenciales de Supabase local automáticamente. No copies claves institucionales ni de producción.

cd ~/src/Develop-SIHS
test -f backend/.env || cp backend/.env.example backend/.env
chmod 600 backend/.env

La IA requiere una GEMINI_API_KEY válida en backend/.env. Sin ella, el resto de SIHS funciona, pero el asistente IA no genera propuestas.

2

Levantar todo

make demo-up

La primera ejecución tarda varios minutos porque Docker descarga y construye imágenes.

No reemplaces este paso con docker compose -f compose.demo.yml up. make demo-up inicia Supabase y entrega al backend las variables locales necesarias.
3

Verificar

make demo-info
docker compose -f compose.demo.yml ps
supabase status
curl -fsS http://127.0.0.1:8000/api/v1/health

Abrir SIHS desde Windows

En el navegador normal de Windows abre estas direcciones:

Comandos de uso diario

ComandoQué hace
make demo-upInicia Supabase local, backend, frontend y Mailpit.
make demo-infoMuestra URLs y cuentas ficticias.
make demo-urlsMuestra solo las direcciones de acceso.
make demo-downDetiene la demo local.
make demo-resetBorra los datos locales de demo y los reconstruye. Úsalo solo para comenzar de cero.
docker compose -f compose.demo.yml logs --tail=100 backend frontend mailpitMuestra registros cuando algo falla.
Rutina diaria: abre Docker Desktop, abre Ubuntu, entra con cd ~/src/Develop-SIHS y ejecuta make demo-up. Al terminar usa make demo-down.

Problemas frecuentes

“make: command not found”

Estás en PowerShell o falta Make. Abre Ubuntu y ejecuta:

sudo apt install -y make
“supabase: command not found”

Instala el paquete .deb dentro de Ubuntu en el paso 4. Luego confirma con supabase --version.

“Cannot connect to the Docker daemon”

Abre Docker Desktop y revisa que Ubuntu esté habilitado en WSL Integration. Después, en PowerShell:

wsl --shutdown

Vuelve a abrir Ubuntu.

SIHS no abre en el navegador

Desde Ubuntu revisa estado y registros:

cd ~/src/Develop-SIHS
docker compose -f compose.demo.yml ps
docker compose -f compose.demo.yml logs --tail=100 backend frontend mailpit
Mailpit no recibe correos

Comprueba el estado y configuración efectiva:

docker compose -f compose.demo.yml ps
docker exec sihs-demo-backend-1 python -c "from app.core.config import settings; from app.services.email_service import EmailService; print('APP_ENV:', settings.app_env); print('SMTP:', settings.smtp_host, settings.smtp_port); print('Configurado:', EmailService.smtp_configurado())"

Debe indicar APP_ENV: demo, SMTP: mailpit 1025 y Configurado: True.

El asistente IA no está disponible

La demo básica funciona sin IA. Para usar el asistente se requiere GEMINI_API_KEY en backend/.env. Nunca compartas esa clave en chats, capturas o commits.

Lista final

  • Ubuntu aparece como versión 2 en wsl --list --verbose.
  • Docker Desktop está abierto y Ubuntu está habilitado.
  • docker version, make --version y supabase --version funcionan en Ubuntu.
  • El repositorio está en fixes-multiples-nicol.
  • make demo-up finaliza sin errores.
  • SIHS abre en http://127.0.0.1:5173 y Mailpit en http://127.0.0.1:8025.
